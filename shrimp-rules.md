# Development Guidelines

AI Agent operational rules for the `C:\workspace` root. This root is a **workspace container**, not a project — it has no `package.json`, no build, and is not itself a git repository.

## 1. Workspace Overview

- **Root purpose**: Hosts the local checkout of `mcp-shrimp-task-manager` and the `.mcp.json` config that wires it up as an MCP server for this session.
- **Contents**:
  - `.mcp.json` — registers the `shrimp-task-manager` MCP server. `command: node`, `args: ["C:/workspace/mcp-shrimp-task-manager/dist/index.js"]`, `env.DATA_DIR: "C:/workspace/mcp-shrimp-task-manager/shrimp_data"`.
  - `.claude/settings.local.json` — enables the `shrimp-task-manager` MCP server for this session.
  - `mcp-shrimp-task-manager/` — the actual project (git repo, npm package `mcp-shrimp-task-manager`, TypeScript/Node/Express/Zod/vitest). This is the only directory with real source code.
- **Do not** treat `C:\workspace` itself as the project root when doing coding work — it never is. Any task that touches source, tests, docs, or dependencies belongs inside `mcp-shrimp-task-manager/`.

## 2. Where Coding Rules Live

- **`mcp-shrimp-task-manager/shrimp-rules.md`** (and its `shrimp-rules.en.md` counterpart) already define full AI Agent development guidelines for that project — naming conventions, architecture, Zod/TypeScript rules, workflow, prohibitions.
- **Must** read and follow `mcp-shrimp-task-manager/shrimp-rules.md` before making any code change inside `mcp-shrimp-task-manager/`.
- **Must not** duplicate or re-derive those rules into this root-level file. This file (`C:\workspace\shrimp-rules.md`) only covers workspace-level layout and cross-cutting operational concerns that the subproject file does not (and should not) cover.
- If those per-project rules go stale, update them in place inside `mcp-shrimp-task-manager/`, not here.

## 3. MCP Server / Build Interaction

- The `shrimp-task-manager` MCP tools used in this session are served from the **compiled** `mcp-shrimp-task-manager/dist/index.js`, not from `src/`.
- **Must** run `npm run build` inside `mcp-shrimp-task-manager/` after editing anything under `mcp-shrimp-task-manager/src/` if the change needs to be reflected in this session's MCP tool behavior (`dist/` is a `tsc` build output plus copied `src/public` and `.md` assets — see the `build` script in `mcp-shrimp-task-manager/package.json`).
- **Must not** hand-edit files under `mcp-shrimp-task-manager/dist/` — they are regenerated by the build and any manual edit will be silently discarded on the next `npm run build`.
- Task data (`plan_task`, `split_tasks`, etc.) is persisted under `mcp-shrimp-task-manager/shrimp_data/` per the `DATA_DIR` env var in `.mcp.json`. **Do not** move or rename that directory without updating `DATA_DIR` in `.mcp.json` to match, or the running MCP server will stop finding task state.

## 4. Prohibited Actions

- **Do not** create a `package.json`, `tsconfig.json`, or other project-scaffolding file directly under `C:\workspace` — there is exactly one project in this workspace and it already lives in `mcp-shrimp-task-manager/`.
- **Do not** `git init` at `C:\workspace` — version control is already scoped to `mcp-shrimp-task-manager/`, which has its own `.git`.
- **Do not** edit `.mcp.json`'s `args`/`env` paths casually — they are absolute paths (`C:/workspace/mcp-shrimp-task-manager/...`) that this running session's MCP connection depends on; changing them requires restarting the MCP server connection to take effect.
- **Do not** modify `mcp-shrimp-task-manager/dist/` by hand (see §3).
